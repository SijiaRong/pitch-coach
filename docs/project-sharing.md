# 公开报告、扫码与项目参与

本功能默认关闭真实分享存储与收款。无需任何密钥，可在示例报告中体验公开设置、免费完整评估、资料解锁、四档打赏和再次发起评估。演示项目、评分和联系人均为虚构；演示不产生订单、不扣款、不上传访客联系方式。

## 项目方决定披露范围

1. 从自己的报告进入“公开完整评估，添加扫码入口”。预览免费公开的评分、四类风险、全部评审与改进清单，单独确认公开。
2. 默认隐藏标题，但这不自动脱敏报告正文。原文摘录可能包含项目数据；确认公开的信息在扫码后免费可见。
3. 可单独开启投资人付费解锁。另行提供完整项目正文、联系人与联系渠道，并明确确认购买核验后披露。原 BP 文件不作为附件保存；支持先提取为文字，由项目方检查完整性。资料包不会自动发送给 AI。
4. 解锁价格推荐 8.88、88.88、888.88、8888.88 元，支持 0.01–99999.99 元自定义。自定义价必须有微信已发布的同价商品才能付款，不会自动换成别的金额。
5. 可单独开启自愿打赏，固定上述四档。支持者可留联系方式并另行授权仅向项目方披露；不承诺股权、收益或回馈。
6. 开启任一收款入口，须确认平台统一收款和 5% 服务费规则。公开同意、私密资料披露同意、服务费同意均默认未选中。

访客身份由本人声明，不代表投资人资质已核验。平台不会自动发布朋友圈。图片分享仍由用户在微信菜单中选择并确认，保存图片为次要按钮。

## 扫码入口

- 微信海报用官方 `getwxacodeunlimit` 小程序码，固定页面 `pages/project/index`，scene 仅为 22 字符随机公开 ID，未编码 BP、联系方式或本机报告 ID。扫码后可免费查看完整评估，也可上传自己的项目。
- H5 可按 `PUBLIC_WEB_URL` 生成指向同一公开页的普通网页二维码。小程序图片分享菜单不使用普通网页二维码，避免与微信图片分享能力限制冲突。
- 未配置官方码服务或公开网页地址时，不返回假码。真实项目缺码会提示生成失败；虚构示例可退回不含码的海报并明确标识。
- 示例码使用经过白名单校验的紧凑场景，携带行业、轮次、偏好、示例价格及匿名设置，不关联真实项目。开发时配置 localhost 只能在本机打开；手机扫描须使用可访问的公网域名或正式小程序码。
- 访问次数为请求次数，发起评估计数为公开项目入口引导的已接收任务数，均不表示去重用户或完成转化。

## 平台收款与 5% 账本

金额全程使用整数分。每笔订单的微信已核实实收 `paid_fee` 扣除已核实退款后，按 5% 四舍五入到分计算平台服务费，其余为项目方份额。例如净实收 88.88 元，对应平台 4.44 元、项目方 84.44 元。退款后重新计算，重复退款通知不会重复入账。

订单标价 `order_fee`、实际付款、退款、服务费、项目方份额、微信返回的渠道费用分别记录。渠道费用的承担和最终结算由运营方与项目方的实际方案确定，不擅自把它视为零或再次从项目方扣除。微信未提供实际付款或退款信息时，该笔标为待对账，不按标价推算收入。总账覆盖全部订单，最近 1000 笔展示限制不截断汇总。

当前代码提供内部记账、查询、权限、退款通知处理与对账准备；**没有自动提现、转账、向项目方付款或主动发起退款**。`pending_external` 不是可提现余额。平台统一收款并向不同项目方结算前，运营方仍须确认可用的微信产品权限、商品类目、渠道费用、退款、对账及项目方结算安排；`PROJECT_SETTLEMENT_READY` 由运营方完成这些准备后设置，程序不会代替资金结算资质或平台审核。

## 开启后台持久分享

在服务器私有环境中设置，不能写进小程序构建变量或提交仓库：

```dotenv
PROJECT_SHARING_ENABLED=true
PROJECT_DATABASE_PATH=/srv/pitchcoach-data/projects.sqlite
PROJECT_DATA_KEY=<32随机字节编码为64位十六进制>
OWNER_ID_SECRET=<至少32字符的稳定随机密钥>
SESSION_SECRET=<至少32字符的独立随机密钥>
WECHAT_APP_ID=<自己的AppID>
WECHAT_APP_SECRET=<自己的AppSecret>
MINIPROGRAM_ENV=release
PUBLIC_WEB_URL=https://你的可选公开网页域名
VIRTUALPAY_ENABLED=false
```

SQLite 数据目录必须在持久卷，不能位于静态网站目录或仓库中。私密资料、联系方式、留言和微信身份使用 AES-256-GCM 加密，密文绑定项目/订单上下文。数据库和加密密钥分别备份、限制权限；丢失密钥将无法交付已经购买的资料。当前为单进程 SQLite 实现，不能直接扩成多个写入实例。

真实报告由后台签发仅供本人的发布凭证，有效 30 天。前端不能伪造高分、发布他人报告或把固定演示作为真实项目发布。旧报告缺凭证时需重新评估。修改 `SESSION_SECRET` 会使旧会话及发布凭证失效，`OWNER_ID_SECRET` 保持稳定以保留订单归属。

## 准备微信虚拟支付

资料访问和自愿支持按虚拟支付接入准备，不能把普通微信支付商户号当作 OfferID/AppKey。当前不支持回退到普通 JSAPI 支付。取得实际产品权限和已发布商品后，设置：

```dotenv
VIRTUALPAY_OFFER_ID=<OfferID>
VIRTUALPAY_APP_KEY=<服务端AppKey>
VIRTUALPAY_PRODUCTS={"unlock:8888":"已发布的88.88元解锁商品ID","tip:888":"已发布的8.88元打赏商品ID"}
WECHAT_MESSAGE_TOKEN=<微信消息推送Token>
WECHAT_ENCODING_AES_KEY=<43字符EncodingAESKey>
PROJECT_SETTLEMENT_READY=true
VIRTUALPAY_ENABLED=true
```

以上商品 ID 是格式示例，必须替换，其他价位也需逐一映射；不能直接上线示例字符串。WeChat 后台消息推送 URL 为 `https://后台域名/api/payments/wechat/notify`，选择 **XML、安全模式**，Token、EncodingAESKey 与 AppID 一致。启动时检查所需配置，缺项时拒绝开启收款。正式开启前应先以测试环境/测试账号完成官方产品联调；当前签名参数为生产 `env=0`，仓库测试使用替身服务，不会向微信发起付款。

前端使用 `wx.requestVirtualPayment`。服务端绑定用户、已确认版本、商品、金额和资料快照，计算 AppKey 支付签名及仅存服务端的 session_key 用户签名。真实支付需手机微信支持该接口与对应系统能力；H5 和模拟器只体验演示。iOS 版本检查是客户端提示，不能代替账号的 IAP 开通与审核。

**前端返回支付成功不授予资料访问。** 后台通过微信 `query_order` 核对订单号、标价、环境和订单类型，持久记录权限，再幂等通知发货。加密回调先校验微信消息签名、解密并验证接收 AppID；发货事件再次查单，退款成功事件撤销后续资料访问。后台定期轮询部分待核对订单，可重启后继续核对。不能在本机超时后丢弃订单快照，否则迟到的付款无法交付。

在微信公众平台设置实际后台为 `request`、`uploadFile`、`downloadFile` 合法域名。小程序包填写自己的 AppID、HTTPS API 地址并重新构建，发布含 `pages/project/index` 的版本后才能生成 release 码。

## 停止分享、退款与资料保存

项目方在“我的公开项目与购买记录”管理价格、打赏开关或停止新分享。停止后公开页、新购买和新取码不可用；已购买者仍可从自己的订单读取购买时的资料快照。改变价格不会改变旧订单或重新收取已购买者费用。

核实退款后关闭该笔资料的后续访问，隐藏项目方页面中的该笔联系线索；无法追回用户此前看到、保存或复制的资料。退款由微信/运营方支持的渠道处理，本项目仅接收最终结果并核对。订单、授权范围和已购买资料的保存期限、删除流程及备份清理由运营方依据实际履约与适用要求制定，不能靠清空本机报告删除后台记录。

默认真实评估仍为临时内存处理，只有项目方单独确认公开、提供解锁资料或参与真实交易后，才进入上述持久存储。请同步更新微信隐私保护指引、应用告知和实际部署材料，不能沿用“任何正文均不入库”的旧说明。
