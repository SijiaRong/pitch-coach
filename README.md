## 它做什么

填项目名称、赛道、目标融资轮次、产品阶段和一段简要介绍，按需上传 BP。从 288 位专项教练中匹配三位不同偏好的投资人，分别审阅，给出有依据的评分、红橙旗、条件性死亡预言、关键假设和模拟投资结论。本机生成海报，预览后优先分享到朋友圈，同时保留保存图片。

- **简洁输入**：一句话介绍是核心，BP 为可选补充；支持 PDF、PPTX、DOCX、TXT、Markdown 的文字提取。
- **行业 × 轮次 × 偏好匹配**：每个行业与轮次都有六位不同偏好的专项教练，共 288 位。每位有独立姓名与 ID、行业证据、阶段问题和补证任务。
- **可更换的三人投委会**：默认技术壁垒、增长验证、财务回报三种视角，也可选择产品客户、团队执行、产业战略。每场恰好三种不同偏好，仍只进行三次模型调用。
- **独立三人评审**：3 次并行模型调用，可按角色分别配置服务商与模型。
- **八维拆解**：痛点强度、市场空间、产品价值、竞争壁垒、增长验证、商业模式、团队适配、融资逻辑。
- **两种语气**：犀利版直戳商业逻辑；专业版冷静、建设性。点评针对项目，不羞辱个人。
- **有证据才评分**：模型必须引用原文，无法匹配的引用被剔除；缺资料标记“待补”，不强行给零分。
- **红旗优先于总分**：明确阻断必须引用资料原文，并附追问和解除条件；任一有效红旗都会阻断推进，不能被高分平均掉。无法核对的红旗降为待澄清问题。
- **把没答清楚的问题亮出来**：橙旗列缺失证据、投资人追问和补证方法；关键假设列最小实验、通过标准；死亡预言列触发条件、失败链条、预警和预防方法。
- **明确的下一步**：最多四项按优先级排序的改进任务，可一键复制。
- **朋友圈优先**：主按钮打开微信图片分享菜单，由用户选择朋友圈；保存图片为次要选项。海报默认匿名，以风险类别、数量和受控条件文案标识四类诊断，不带 BP 原文、详细追问或私密金额；默认分享首页，单独确认公开后可扫码查看完整评估。
- **本机与云端**：本机保留 20 份；主动微信登录并开启云端保存后，真实报告加密保存、归属微信身份，最多 100 份，支持跨设备查看和单独删除。
- **离线演示**：无需 Key 即可查看各行业和轮次的虚构示例，固定评分有明显标识；真实调用失败不会伪装成 AI 结果。

## 288 位教练如何匹配

人工智能、企业服务、消费品牌、硬件科技、医疗健康、新能源与气候、金融科技、其他创新，共八个领域。每个领域的每个融资轮次都有六位专项教练：

- **技术壁垒**：技术与工艺的可复现性、独有资产和复制难度。
- **增长验证**：用户行为、付费、留存、复购和渠道可复制性。
- **财务回报**：完整成本、现金消耗、资金用途与阶段预算。
- **产品客户**：客户工作流、替代方案、实际价值和持续使用。
- **团队执行**：创始人适配、岗位分工、复盘和组织承接能力。
- **产业战略**：价值链位置、上下游依赖、议价和竞争应对。

融资轮次独立于产品阶段：

- **种子轮**：问题是否真实，团队为什么适合，最小实验怎么做。
- **天使轮**：早期反馈、产品迭代、付费意愿与验证里程碑。
- **Pre-A**：留存、初步单位经济、渠道和产品市场匹配信号。
- **A 轮**：增长能否复制，销售交付与组织能否承接规模。
- **B 轮**：规模下的效率、现金流、利润路径与竞争韧性。
- **C 轮及以后**：盈利质量、治理、资本配置与可论证的退出路径。

例如，“硬件科技 × 种子轮 × 技术壁垒”追问原型验证和失败判据；“硬件科技 × A 轮 × 技术壁垒”追问量产可靠性和规模下的技术优势；同一行业与轮次的财务派则核算备货、返修和账期。偏好影响追问，不放宽八维评分的证据要求。

“AI 投委会”页按行业、轮次和偏好筛选，可直接邀请某位教练；提交页可更换三人组合。288 指有专属定位与提示内容的角色数量，不代表 288 个独立训练的基础模型。演示报告使用固定评分。早期版本的 15 个角色保留为旧报告与模型配置的兼容资料，不计入可选名单。

**这些角色全部虚构，不是任何真实人物或机构的代言。**

## 本地运行

需要 Node.js **22.13+** 与 pnpm **11.25.0**。在 Node.js 24.19.0 上完成本地验证，CI 使用 Node.js 22。

```sh
git clone https://github.com/SijiaRong/pitch-coach.git
cd pitch-coach
corepack enable
corepack prepare pnpm@11.25.0 --activate
pnpm install --frozen-lockfile
pnpm dev
```

浏览器打开 [本地预览](http://localhost:5173)，API 运行在 `127.0.0.1:8787`。没有模型 Key 时也能完整体验演示报告、行业轮次匹配、历史记录与海报。H5 是同一套小程序源码的开发预览，不是微信发布链接。

### 接入真实 AI

把根目录 `.env.example` 复制为 `.env`，只在后台设置：

```dotenv
AI_BASE_URL=https://api.deepseek.com
AI_API_KEY=你的服务端密钥
AI_MODEL=deepseek-flash
```

重启 API，勾选资料处理说明后即可评估真实项目。采用 Chat Completions 兼容接口，可更换支持该协议的模型服务。`AI_BASE_URL` 应是 API 根地址，需要时包含 `/v1`，不要包含 `/chat/completions`。

默认使用 JSON mode 与严格的服务端结果校验。若服务商不支持 `response_format`，设置 `AI_JSON_MODE=false`；结果仍必须是符合结构的 JSON。模型 ID 以服务商当前可用的 ID 为准。

可按精确角色、投资偏好、融资轮次或行业覆盖 `BASE_URL`、`API_KEY`、`MODEL`。每个字段依次查找：精确角色 → 偏好 → 轮次 → 行业 → 旧角色兼容配置 → 全局默认。例如：

```dotenv
AI_PREFERENCE_TECHNOLOGY_MODEL=你的技术评审模型
AI_PREFERENCE_FINANCIAL_BASE_URL=https://你的财务模型服务/v1
AI_PREFERENCE_FINANCIAL_API_KEY=另一个服务端密钥
AI_PREFERENCE_FINANCIAL_MODEL=你的财务模型
AI_ROUND_SEED_MODEL=你的种子轮模型
AI_INDUSTRY_HARDWARE_MODEL=你的硬件行业模型
AI_HARDWARE_A_TECHNOLOGY_MODEL=硬件A轮技术壁垒专项模型
```

精确角色 ID 采用 `行业-轮次-偏好`，配置时将 `-` 改成 `_` 并转大写。角色定义见 [catalog.ts](packages/shared/src/catalog.ts)，专项问题见 [preferences.ts](packages/shared/src/preferences.ts)，配置见 [.env.example](.env.example)。无需为 288 个角色分别配置密钥，只配全局模型即可。**密钥不要放进前端、仓库或微信小程序包。**

### 编译微信小程序

只想在模拟器中体验 Demo，可以先不配置 AppID 或后台：

1. 安装并登录[微信开发者工具](https://developers.weixin.qq.com/miniprogram/dev/devtools/download.html)。
2. 运行 `pnpm build:weixin`，在开发者工具中导入 `apps/miniprogram/dist/build/mp-weixin`。
3. 在导入页选择“测试号”，后端服务选择“不使用云服务”；出现项目作者信任提示时，确认来源后运行。
4. 等待首次编译完成，点击首页“示例报告”，或进入“项目评估”选择行业、融资轮次与三种偏好后查看对应示例。演示完全在本地生成，不需要 API Key。

部分新版工具不接受默认的 `touristappid`，请使用导入页提供的“测试号”入口。开发者工具会把所选测试 AppID 写入本机的 `dist` 配置，该目录已被 Git 忽略。重新构建后，可能需要再次选择测试号。测试号用于开发体验，不能代替正式发布所需的小程序账号。

连接真实后台或准备发布时：

1. 在 `apps/miniprogram/src/manifest.json` 的 `mp-weixin.appid` 填入自己的小程序 AppID。
2. 把 `apps/miniprogram/.env.example` 复制为该目录下的 `.env.local`，配置 `VITE_API_BASE_URL=https://你的后台域名`。此变量是公开的 API 地址，不是密钥。
3. 运行 `pnpm build:weixin`。
4. 在微信开发者工具中导入 `apps/miniprogram/dist/build/mp-weixin`。
5. 在微信公众平台配置后台域名为合法的 `request` 与 `uploadFile` 域名。

微信实际发布需要你的小程序账号、AppID、后台 HTTPS 服务以及平台审核。仓库不附带任何账号凭据。开发时可用 `pnpm dev:weixin` 生成带监听的 `dist/dev/mp-weixin`。

## 评分规则

行业基础权重乘以融资轮次的关注系数，归一化为合计 100 的整数权重。不同轮次是不同的评审标准，不是给后期项目加分。

```text
单项得分 = 完成评审且具有原文证据的投资人评分均值
参考总分 = Σ(已评分维度得分 × 组合权重) / Σ(已评分维度权重)
证据覆盖 = Σ(已评分维度权重)
```

总分是自检参考，不是成功概率或估值。原文匹配只能排除一部分捏造引用，不能验证用户陈述是否真实，也不能消除模型在推理和建议中的错误。

- 任一评审识别到能匹配资料原文的阻断红旗：**红旗阻断**（`verdict=pass`），解除前暂停推进；该规则优先于总分和其他投票。
- 无阻断红旗时，覆盖不足 60%、只有一位评审完成，或至少两位评审认为资料不足：**资料不足**。
- 三位全部完成、至少两位愿意推进、覆盖至少 80%，且没有关键待答橙旗或未经验证的关键假设：**愿意推进**，仅表示模拟中愿意进一步尽调。
- 关键橙旗或假设尚未解决时，原本的推进票改为观察，最终结论最多为**补证再议 / 假设待验**，也可因其他不足维持暂不投资或资料不足。
- 至少两位不投：**暂不投资**。
- 其他情况：**继续观察**。

部分模型失败时展示缺席角色并保守处理；全部失败时返回明确错误。算法与边界测试见 [scoring.test.ts](packages/shared/src/scoring.test.ts)。

四类诊断按实际完成的评审合并并记录提出者，同一判断不重复计数。未检查过这些项目的旧报告明确标为“未检查”，不会显示为零风险；重新评估后才有完整诊断。诊断及门槛测试见 [diagnostics.test.ts](packages/shared/src/diagnostics.test.ts)。早期没有收入、硬件或医疗验证周期长不自动算作红旗；“死亡预言”是条件性推演，不提供必死断言或死亡概率。

分享使用微信 [`wx.showShareImageMenu`](https://developers.weixin.qq.com/miniprogram/dev/api/share/wx.showShareImageMenu.html)。朋友圈图片分享需要支持该能力的微信基础库（3.8.2+）；微信海报使用官方小程序码，H5 可使用配置域名的网页二维码。模拟器、浏览器和旧版环境可能只能打开大图预览，页面会给出提示。用户取消不会自动保存、重试或发布；菜单打开成功也不当作发布成功。微信真机的最终发布由用户确认。

## 技术与数据流

```text
uni-app / Vue 3 / TypeScript
  ├─ 微信小程序 / H5 开发预览
  ├─ 输入 → 行业 × 轮次匹配 → 资料处理同意
  ├─ BP 文件 → 受限隔离解析提取文字 → 用户可检查正文
  └─ 提交文字 → Fastify API → 三位投资人并行审阅
                            → JSON 校验 / 原文证据核验 / 加权汇总
                            → 本机报告 / 改进清单 / Canvas 海报
```

```text
apps/miniprogram/        小程序与 H5 预览，共用页面和交互
apps/api/                会话、上传解析、模型适配与异步任务
packages/shared/         行业、轮次、角色、结构、评分与虚构示例
docs/deployment.md       生产部署、环境配置与运行边界
docs/api.md              API 契约与错误处理
```

普通评估的原始 BP 与正文不入库。主动公开的评估、另行授权的资料正文与联系人、云端报告使用可选持久存储，私密内容加密。文件解析在受限实例中完成，Windows 的 PDF 使用独立进程，其余使用工作线程；上传最大 10 MB，PDF/PPTX 最多 80 页，提取正文最多 50,000 字。扫描件 / 图片 BP 暂不支持 OCR。后台报告缓存最多 10 分钟，客户端领取后请求删除。启用微信支付时，订单和额度持久保存；完成报告以加密形式短期缓存，重启后仍可在有效期内领取，未完成任务恢复额度。未启用支付时任务仍为内存实现。

生产环境使用微信登录换取签名会话。默认最多两份评估同时运行；免费开发模式每位用户每滚动 24 小时五次。可开启微信支付，每次真实评审 ¥1.88，演示免费；失败或取消恢复额度，部分完成的报告计一次。付费账本使用独立 SQLite，目前仅支持单实例，人工退款步骤见 [支付接入说明](docs/payments.md)。更完整说明见 [部署文档](docs/deployment.md)。
